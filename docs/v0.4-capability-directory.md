# v0.4 设计：能力目录与预设编辑

> 状态：**已实现（v0.4.0）**。本文件记录用户 2026-11-08 提出的三项改造（能力目录、预设独立编辑、
> 删除修复），实现按 §4 确认的岔路口落地，落地记录见 §7。

---

## 1. 要解决的问题

### 1.1 目前的分类是「按类别」，不是「按用途」

现在无论设置页还是会话面板，能力都按 **MCP / 插件能力 / Skills** 三段平铺。用户真实的心理模型是**场景**：

```
浏览器
  ├ MCP     chrome
  └ Skills  7 个浏览器相关 skill
长期记忆
  ├ 插件能力  dsh-project-memory
  └ Skills    memory-* 
```

同一个目录里可以混装三种类别。所以需要一层**用户自己维护的目录**，目录是顶层，类别只在目录内部
作为小节出现。

### 1.2 预设不该「只能从当前会话长出来」

现状：会话面板里调开关 → 「存为方案」/「更新方案」；设置页的「新建方案」也是以默认方案为内容起点。
用户要的是：**一个独立的「创建能力预设」的地方，在那里勾选各种能力，勾选过程与当前会话完全无关**。

### 1.3 删除方案点了没反应

根因已定位：客户端用的是 `window.confirm`，桌面壳会抑制原生对话框，`confirm` 直接返回 `false`，
于是删除、应用方案、释放插件等所有「确认后执行」的动作都变成静默空操作，`window.alert` 的报错
也看不见。**已修**：改为应用内对话框（`DialogHost`），并加了回归测试
（`client-dom-test.mjs` 的 `presetDeleteOpensInAppDialog` / `noNativeDialogsUsed`）。

## 2. 能力目录（catalog）

### 2.1 概念

三级词保持不变：**能力包（bundle） → 能力方案（preset） → 默认方案**。能力目录是**平行于方案的组织维度**：

| | 是什么 | 影响运行吗 |
|---|---|---|
| 能力目录 | 用户给**已安装能力**分的组（场景/主题） | 否，只影响展示与勾选效率 |
| 能力方案 | 一个会话应有的完整能力集合 | 是 |

一个目录 = 一个名字 + 一组成员 `{kind, id}`，`kind ∈ mcp | skill | provider`。
目录里按类别显示成三小节；空类别不显示。

### 2.2 数据模型（`library.json`，仍是 version 2）

```jsonc
"catalogs": [
  {
    "id": "catalog-xxx",
    "name": "浏览器",
    "order": 0,
    "members": [
      { "kind": "mcp", "id": "mcp-abc" },
      { "kind": "provider", "id": "provider-xyz" },
      { "kind": "skill", "id": "playwright" }
    ],
    "createdAt": "ISO", "updatedAt": "ISO"
  }
]
```

- **一个能力最多属于一个目录**（默认）——避免同一项在两个目录里出现两次、两个开关互相打架。
  未归入任何目录的能力显示在「未归入目录」组里，不丢失。
- 目录指向的能力被删除/卸载时**保留成员记录**，解析时报 `missing`（与预设一致，不静默收缩）。
- 目录名唯一（重名自动加序号），支持排序。

### 2.3 UI

**会话面板**新增第三个 tab，与「本次会话」「模型视图」同级：**「能力目录」**。

```
[能力目录]                                    [新建目录] [刷新]
▸ 浏览器                                    3 项 · 已启用 2      [全选] [全部关闭]
    MCP       chrome                    [开关] 已连接
    插件能力  -                          -
    Skills    playwright / puppeteer / … [三态]
▸ 长期记忆                                  2 项 · 已启用 2
    插件能力  dsh-project-memory        [开关] 已挂载
    Skills    memory-write              [三态]
▸ 未归入目录                                5 项
    …
```

- 每个成员行复用现有控件（MCP 开关 / Skill 三态 / provider 开关），行为与「本次会话」tab 完全一致。
- 目录行提供：全选 / 全部关闭 / 改名 / 删除 / 添加成员。删除目录**不删除能力**，只解除分组。
- 「添加成员」是一个多选对话框，列出尚未归入该目录的能力。

**设置页**：新增「能力目录」tab 做集中管理（建、改名、删除、增删成员、排序）。
会话面板那个 tab 用于浏览与开关；两边读写同一份 `library.catalogs`。

**预设编辑器**：按目录分组呈现（见 §3）。

### 2.4 API

```
listCatalogs()                     // 目录 + 解析后的成员（含 missing 标记）
saveCatalog({ catalog })           // create/update（按 id 有无）
deleteCatalog({ id })
setCatalogMembers({ id, members })
```
`getSettings()` 增加 `catalogs`，`getSession()` 增加 `catalogs`（面板要用）。

## 3. 预设的独立编辑

### 3.1 现在的流程

设置 → 能力方案 → 新建方案 → 弹窗（MCP 一节、插件一节、Skills 一节，全部平铺）。
这已经「与当前会话无关」，但两件事让它看起来不像：

1. 新建时**以默认方案为内容起点**，用户会误以为是「复制当前」；
2. 三节平铺、不能按场景成组勾选，勾 7 个浏览器 skill 要点 7 下鼠标。

### 3.2 目标

设置 → 能力方案 → **「创建能力预设」**（主按钮，与「导入方案」并列），打开一个**全宽编辑器**：

```
名称 [                    ]     模式 (快照 / 基线)
[ ] 以默认方案为起点          ← 默认不勾；勾了才复制基线内容

按目录勾选
▸ 浏览器        [全选] [全不选]   1/10
    MCP      ☑ chrome
    插件能力  ☐ -
    Skills   ☑ playwright ☑ puppeteer …
▸ 长期记忆      [全选] [全不选]   2/2
    …
▸ 未归入目录                     3/8
    …
```

- 勾选粒度是**单个能力**；目录提供全选/全不选，只是批量操作。
- 编辑器只读写**预设自身**的 `mcp / skills / plugins.desired`，从不读会话状态。
- Skills 的 `auto/manual/off` 三态在编辑器里也用三态控件（现在已有），目录内按三态展示。
- 编辑已有方案时同样按目录分组的视图打开。

### 3.3 会话面板保留的入口

「存为方案」保留：从当前会话孵化一个方案是合理需求；但它是**次要入口**，主入口是设置页的
「创建能力预设」。会话面板的按钮文案要明确「用本次会话的选择新建方案」。

## 4. 岔路口（已确认，2026-11-08）

1. **一个能力能否属于多个目录？** → **可以**。同一能力出现在多个目录里，开关在多处同步；
   目录内至少出现一次（`normalizeMembers` 去重）。
2. **新建预设时默认的起点？** → **空白**，另给「以默认方案为起点」复选框。
   勾选时把默认方案的内容复制进来，取消则清空回白纸。
3. **目录的管理入口放哪？** → **两处都有**：会话面板新增「能力目录」栏（浏览 + 开关 + 就地增删改），
   设置页新增「能力目录」tab（集中管理）。两边读同一份 `library.catalogs`。

## 7. 落地记录（v0.4.0）

| 层 | 改动 |
|---|---|
| `host/catalogs.js`（新） | `normalizeCatalog` / `normalizeMembers` / `memberKey` / `cloneCatalog` / `sortCatalogs` / `resolveCatalog` / `resolveCatalogs` / `unfiledCapabilities` |
| `host/store.js` | `listCatalogs` / `getCatalog` / `upsertCatalog` / `setCatalogMembers` / `deleteCatalog` / `uniqueCatalogName`；`normalizeLibrary` 增加 `catalogs`（缺省 `[]`，v0.2/v0.3 库免迁移） |

| `client.js` | 设置页「能力目录」tab + `CatalogEditor`；会话面板第三个 tab「能力目录」+ 目录级全选/全部关闭；预设编辑器按目录分组、新建默认空白 + 「以默认方案为起点」 |

行为细则：

- 目录成员被删/卸载后**保留在目录里**并标记 `present: false`，UI 显示「已不存在」，与预设引用一致。
- `未归入目录` 由 `unfiledCapabilities` 计算：不在**任何**目录里的能力，保证总有一个入口能勾到它。
- 会话面板的目录开关复用「本次会话」tab 的处理函数（MCP 开关 / Skill 三态 / provider 开关），
  只是换了分组方式；目录级全选/全部关闭也是一次 `saveSession` 手动调整（会让会话 dirty）。
- 预设编辑器：目录只是分组，勾选粒度仍是单个能力；`initial` 只用于 update 模式，
  create 模式默认全空。

测试：`spike/catalog-store-test.mjs`（目录模型纯函数 + store + 兼容），
`spike/host-api-test.mjs` 增目录 API 用例，`spike/client-dom-test.mjs` 增目录 tab、目录编辑器、
编辑器按目录分组共 7 项断言。

## 8. 2026-11-08 第二轮修订

1. **新方案默认是「基线」（sparse）**，不是快照。编辑器 `mode === 'create'` 初始 `sparse`；
   `savePreset` 创建分支把 `input.skillsMode` 透传给 `store.createPreset`（在此之前它被忽略，
   新建方案永远变成 explicit，这是一个真 bug）。导入方案仍按文件里的 `skillsMode` 走。
2. **会话面板的方案操作独立成条**。页脚只留 `刷新 / 关闭`（会话级）；方案级操作移到方案选择器
   下方的一条 `.ch-preset-bar`：`另存为新方案 / 用当前选择更新方案 / 设为工作区默认`，并注明
   「这些操作改动的是方案本身，不是本会话的能力」。
3. **`link:` 安装的插件改宿主代码必须重启 DSH**。页面（client）随刷新更新，宿主（host）不会：
   `dsh-hmr` 的文件监听根是 **profile 目录**（`this.config.root`），而 link 目标的真实路径在
   `D:\WORKSPACE\…\capability-hub`，不在监听范围内，所以改那里的文件不会唤醒 `reconcileProfile`。
   （`profileRoots()` 确实会把 link 目标算进"模块比较"范围，但那是在 reload 被触发之后才用到的。）
   2026-11-08 现场：宿主进程 21:45 启动、宿主文件 22:09 才写，于是新建目录报 `Unknown action "saveCatalog"`。
   为此加了握手：`host/util.js` 的 `HOST_API` 与客户端 `CLIENT_API` 比对，`getSettings` 返回 `hostApi`，
   不一致时设置页显示横幅、`notifyError` 对 `Unknown action` 给出「宿主端还是旧版本，重启 DSH」的对话框。

## 9. 2026-11-08 第三轮修订：目录树形态

会话面板的「能力目录」是**目录树**，不是一堵开关墙：

1. **目录默认折叠**，可以逐个展开/收起；标题行给出 `N 项 · x MCP · y 插件 · z Skills` 的摘要，
   折叠状态下也能看出里面装了什么。展开状态记在模块级 `expandedCatalogs` 里，关掉面板再打开保持不变。
   工具栏提供「全部展开 / 全部折叠」。
2. **目录内部按类型分组**：`MCP` / `插件能力` / `Skills` 三个小节，各有小标题与数量，小节之间用虚线分隔。
   顺序沿用「MCP → 插件能力 → Skills」。`未归入目录` 是同一个组件的特殊一节（没有编辑/删除/批量按钮）。
3. 目录头部的 `全选 / 全部关闭 / 编辑 / 删除` 常驻（折叠时也能一键整组开关）。
4. 预设编辑器沿用同一套分组标题样式，保证两处观感一致。

DOM 测试覆盖：默认折叠（`sessionCatalogsCollapsedByDefault`）、折叠按钮数量、
展开后出现能力（`sessionCatalogExpands`）、按类型分组的标题（`sessionCatalogGroupsByKind`）、
再次折叠（`sessionCatalogCollapsesAgain`）。

> 本轮只改 `client.js`，刷新页面即可；不需要重启 DSH。

## 10. 2026-11-08 第四轮修订：统一 Skill 的事实源

**现场症状**：设置→能力中心里，目录中的 `office` / `office-docx` … 显示「未安装 / 8 已不存在」，
但同一个会话面板的「能力目录」里它们存在且可切换。

**原因**：两个事实源不一致。

- 会话面板的 Skill 列表来自 harness 的 `skills` 服务（`snapshot({scope, cwd})`），它聚合了
  文件系统、内置 Office/skill provider、插件贡献的 Skill；
- 设置页与目录解析用的是插件自己的 `scanSkills(cwd)`，**只扫 `~/.dsh/skills` 和 `<cwd>/.dsh/skills`**，
  看不到内置 Skill，于是把它们判成 `present: false`。

**修法**：`host/skills.js` 新增 `listInstalledSkills(ctx, cwd)`：

- 以 `ctx.skills.list({ cwd })` 为准（与模型目录、会话策略同源），
- 再合并文件扫描结果（管目录里的文件带 `path`，可删），按名字去重、服务优先；
- 每条带 `removable`（仅两个管理根内为 true）与 `builtin`（服务里有、文件扫描没有）。
- `getSettings`/`getSession` 的 `skills`、目录解析的 `skillNames`、方案捕获的 `knownSkills`
  全部改用它。

**范围结论**（与用户确认的口径一致）：

| 类型 | 管理范围 | 能做什么 |
|---|---|---|
| Skills | **全部**（内置 + 用户 + 项目 + 插件贡献） | 列、按会话/方案切换 `auto/manual/off`；**只有两个管理根可删** |
| MCP | **全部**（DSH 无内置 MCP） | 增删改、按会话挂载 |
| 插件 | **仅第三方** | 注册/接管/按会话挂载；原生插件不在列表里 |

UI：Skills 页对 `removable: false` 的行显示 `内置`，不给「移除」按钮，路径位置显示「内置 Skill，没有可删除的文件」。

测试：`host-api-test` 的 skills mock 返回一个 bundled Skill，断言它出现在 `getSettings().skills`
且 `removable: false`、目录解析 `present: true`；`client-dom-test` 断言内置行有 `内置` 标、无「移除」，
而管理根内的 Skill 仍有「移除」。
